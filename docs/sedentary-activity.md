# 久坐提醒与活动时间轴

## 状态与提醒

久坐状态保存在桌面本地 JSON 的 `sedentary` 字段中，本地状态是唯一运行时真相。

- 用户切换到“坐下”后，从 `seatedSince` 开始按设置的久坐时长计时。
- 首次提醒后，如果仍为坐下状态，以 `lastStandReminderAt` 为锚点每 5 分钟再次提醒。
- 用户切换到“起身”后，停止起身提醒，并每 5 分钟询问是否已经重新坐下。
- 每次状态切换都会清空上一状态的提醒锚点。

调度器每 30 秒核对一次，因此系统通知可能在到期时间后的一个调度周期内出现。

## 当天活动数据

`SedentaryState` 使用以下字段保存活动时间轴：

- `activityDayKey`：本地日期，格式为 `YYYY-MM-DD`。
- `activityEvents`：按发生顺序保存的节点；每项包含 `kind`（`seated` 或 `standing`）和 RFC 3339 时间 `at`。

每次点击底部“坐下/起来”按钮都会原子地切换当前状态并追加节点。活动页根据相邻节点计算阶段时长；最后一个节点持续到当前时间。

坐下阶段不超过 30 分钟显示黄色，超过 30 分钟显示红色并标注“久坐”；起身阶段显示绿色。颜色之外始终保留状态文字。

## 跨日规则

调度器或应用启动加载状态时发现 `activityDayKey` 已不是当天，会清空旧节点并以当前姿态和当前时间创建新一天的起点，同时重置该姿态的提醒计时。活动事件不进入近期 D1 快照，只随本地导出或完整云备份保存。
